# test-strategy — 빌드 성공 + 하드웨어 수동 관찰

이 프로젝트에는 테스트 프레임워크·테스트 디렉토리·CI가 **없다**. 그리고 작업 환경 자체가 타깃 하드웨어(라즈베리파이 5 본체)다 — 에이전트가 빌드·실행을 모두 여기서 직접 할 수 있다. 변경 검증은 다음 2단계로 한다.

1. **빌드 성공(에이전트가 여기서 직접 수행)**: `cmake --build build --parallel`(또는 VS Code "CMake Build")가 경고 없이 통과하는지 확인. 자동 검증의 핵심이다.
2. **실제 동작 확인(에이전트가 직접 가능)**: 동작 확인은 `./install/AutoDrive 1|2|3` 실행으로 한다. 이 바이너리는 실제 모터/서보를 구동해 로봇이 물리적으로 움직이지만, **검증 목적의 짧은 실행·짧은 주행은 에이전트가 직접 해도 된다**. 단 장시간 자율 주행이 아니라 변경 확인에 필요한 최소 실행으로 한정하고, 무엇을 돌리는지 실행 전에 한 줄로 알린다. 사람이 직접 봐야만 하는 물리 시나리오는 완료 보고서의 "사용자가 확인할 것" 체크리스트에 적는다.

**Why:** wiringPi/libcamera/GPIO/I2C/시리얼(`/dev/ttyUSB0`)에 직접 의존하고, 이 호스트가 곧 그 하드웨어다([[project-intent]] 실행/테스트 방법). 빌드도 실행도 여기서 바로 되며, 사용자가 검증용 짧은 실행·주행을 허용했다 — 다만 물리 움직임이 따르므로 최소 범위로 한정한다.

**How to apply:**
- "테스트 추가"를 요청받지 않는 한 단위 테스트 프레임워크를 새로 들이지 않는다. 그게 필요해 보이면 먼저 제안하고 사용자 결정을 받는다.
- 에이전트의 자동 검증은 **빌드 통과 + (필요 시) 검증용 짧은 실행/주행**까지 할 수 있다. 완료 보고 시 무엇을 자동 검증했는지(빌드·짧은 실행 결과)와 무엇이 여전히 사람 관찰을 요하는지 정직하게 구분 보고한다.
